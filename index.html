落盘

文件就是唯一真相源

日志写在项目根目录下，和 CLAUDE.md 同级，随项目一起管理。远程同步交给 Git、feishu-cli 等工具，技能本身不联网。

目录结构

journals/
├── journal-config.json
├── index/
│   └── {USERNAME}-YYYY-MM.json
└── YYYY-MM/
    └── {USERNAME}-YYYY-MM-DD.md

配置参数

参数说明
USERNAME日志文件所属用户名，初始化时确认后不建议修改
JOURNAL_DIR日志根目录绝对路径，默认 {项目根目录}/journals/
initialized初始化标记，由流程自动写入

配置位置：JOURNAL_DIR/journal-config.json， 全局指针 ~/.iris-journal

不触发

git 上下文不会误触发

涉及版本控制的对话整体判为提交意图，即使话里带「总结」「变更」「记录」也不写日志。

用户说的话处理
git commit -m "fix bug"按提交操作处理，不归档
帮我写今天的提交信息生成 commit message，不归档
总结这次 PR 的变更代码评审上下文，不归档
打开昨天的日志看看读取已有日志，本技能只写不读
导出日志为 PDF格式转换超出范围

初始化

首次运行，四步完成配置

新会话没有记忆，但配置文件一直躺在磁盘上。技能每次先找配置，找不到才走初始化。

S0

定位配置

先读全局指针 ~/.iris-journal，再探测 {CWD}/journals/journal-config.json。命中即跳过初始化。

S1

确认用户名

从项目 USER.md 或直接询问取得 USERNAME，展示候选值，确认后才写入。

S2

确认目录

默认 {CWD}/journals/，展示绝对路径供确认。目录已有文件时询问合并还是换路径。

S3

写入并验证

校验字段、创建目录、写 config 与全局指针，再按模板生成当月索引文件。

边界

它只做一件事

范围收得窄，行为才可预期。需要读取、汇总、转换时，用别的工具。

  • 只写不读不提供历史日志检索或浏览
  • 只记当次会话不做跨天、跨会话的汇总报告
  • 不做格式转换不导出 PDF、Excel 等格式
  • 不自动定时归档始终由你主动触发
